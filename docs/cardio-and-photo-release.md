# Cardio logging and photo-analysis investigation

## Cardio: completed-session logging

Open **Log cardio** from Training or a day in Today. Choose an activity and enter
minutes; distance in km, session effort, date and notes are optional. Saved entries
can be reviewed, edited and removed with confirmation. A separate seven-day total
shows minutes and session count. The last three matching activity entries within
90 days provide a median duration, not an instruction to increase it.

Minutes describe duration, not training stimulus or improved fitness. Activity,
terrain, incline, equipment and effort are not interchangeable. Cardio never adds
lifting volume, muscle-set credits, programme completion or estimated food calories.
No automatic 5% increase, heart-rate zones, GPS or fitness score is introduced.

The record uses existing private `wellness_logs` rows (`kind: cardio`, versioned
metadata). SQLite write and sync outbox enqueue share a transaction. Edits retain
the UUID, deletion uses a tombstone, and complete export includes the metadata.
No new SQL migration is needed. Unsupported metadata versions are not overwritten.

This is a manual completed-session logger, not a live workout timer. Saved entries
survive reload; unfinished cardio inputs do not yet have draft recovery. Physical
device testing and real cross-device synchronization remain release gates.

Browser QA exposed a calendar handoff defect: the animated day modal could retain
its focus trap after the destination screen opened. On WebKit, immediate typing
could be redirected away from the cardio field. Day navigation now unmounts the
modal first and opens the destination in a subsequent effect, after focus cleanup.
This applies to the day panel's training, food, cardio and wellness actions. The
regression edits the field immediately after calendar navigation and checks the
saved value and subsequent history; it does not add an arbitrary sleep.

## Photo scan: confirmed production failure, not yet resolved

One user-approved, synthetic nutrition-label image was sent through production.
It returned HTTP 503 with `PROVIDER_UNAVAILABLE`; no meal was saved. Support
reference: `2839f9e2-b63a-4f16-8561-6d3f040f1d46`. The synthetic selection was removed
after inspection. No personal photos, keys or records were copied into test fixtures.

Read-only download of the deployed function showed that its request format and
error classifier match the workspace. The only provider-adapter difference before
this change was label-transcription prompt wording. The configured model reported
by AI settings is `gemini-3.5-flash-lite`. A capability check confirms configuration,
not successful image inference; an old frontend alone does not explain this failure.

The existing generic rejection discards the upstream HTTP status. We cannot name
the provider-side cause from this evidence. Local hardening now:

- Logs only request reference, provider/model, credential source, safe error code,
  upstream HTTP status, allowlisted canonical status and retryability. No keys,
  images, prompts or provider bodies.
- Includes an HTTP status in unexpected non-retryable rejection messages.
- Gives structured Gemini output 4,096 tokens of headroom for up to 12 items,
  rejects non-STOP output and excludes thought parts from food JSON. This addresses
  separate output-integrity risks, not a proven cause of the observed rejection.
- Keeps the photo-selection disclosure accurate after a failed attempt.
- Opens web camera/photo dialogs without a slide animation: the delayed web modal
  focus trap could otherwise steal focus while the user entered context. Native
  dialog animation is unchanged. Browser regression checks the exact description
  sent to the mocked provider and verifies it survives a failed attempt.

Release the photo function separately, then obtain permission for one new synthetic
scan and inspect the safe provider diagnostic. Do not reconnect keys, enable billing
or send repeated requests as speculative fixes. No deployment has been performed
by this change. The live photo fix is not certified until that retest succeeds.
